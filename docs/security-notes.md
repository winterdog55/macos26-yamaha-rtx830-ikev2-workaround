# セキュリティ上の注意

## 事前共有鍵（PSK）の扱い

- 記入後の `.mobileconfig` には **PSK が平文で含まれます**
- メール添付やチャット、公開リポジトリでの共有は避けてください
- 配布が必要な場合は、暗号化した経路（パスワード付きアーカイブ等）を使い、受け取り側でインストール後にファイルを削除するよう案内してください
- 本リポジトリの `.gitignore` は記入済みファイルを除外する設定になっていますが、**最終的な確認は各自で**お願いします

### PSK をファイルに書かない運用（推奨）

`SharedSecret` を空欄のままインストールし、PSK はインストール後にシステム設定の VPN 画面から手動で入力する方法があります。この場合、配布するファイルに秘密情報が一切含まれないため、複数人に配布する場合はこちらが安全です。暗号パラメータの固定はプロファイル側で有効なままなので、回避策としての効果は変わりません。

## パケットキャプチャの扱い

トラブルシューティングで取得した `.pcap` には以下が含まれます。

- グローバル IP アドレス、ホスト名、ユーザー識別子
- 鍵交換に使われる KE ペイロードと Nonce

PSK そのものは平文では出ませんが、環境を特定できる情報が多く含まれるため、**公開リポジトリや掲示板への添付は推奨しません**。ベンダーへ提供する場合も、必要な範囲に絞るか、要求があった場合に個別に送付してください。

## PFS（Perfect Forward Secrecy）について

本テンプレートは検証を単純化するため `EnablePFS` を無効にしています。

セキュリティを優先する場合は、ルーター側の PFS 設定と揃えた上で有効化を検討してください。その際は **1回に1つの設定だけを変更**し、接続確認を取りながら進めることを推奨します（複数を同時に変えると切り分けが困難になります）。

## その他

- 本プロファイルは既知の互換性問題を回避するためのものであり、暗号強度を下げるものではありません（AES-256 / SHA2-256 / DH14 は現行で有効な組み合わせです）
- ルーター側のファームウェアが更新され、本問題が修正された場合は、プロファイルなしの標準構成に戻すことを検討してください
